# Файлы чата: один поток версий на документ

Версия 2 от 2026-10-28, заменяет черновик того же дня. Затронуты: Bridge 1.6.0, серверный агент (co-agent), сервер (схема 12, db.php, cron), CO Web 0.55.0, aiwb-docs.

## 1. Модель

- **Файл чата** — это поток версий одного документа. Его ключ — путь относительно `scratch` чата (`report.docx`, `out/plan.xlsx`).
  Живая копия лежит одна: `chats/<chat>/scratch/<path>` на Drive.
- **Версия** — это ревизия Drive этой живой копии. Её автор:
  - агент: файл менялся во время задания;
  - пользователь: вложение, загруженное как новая версия;
  - Drive: правка мимо чата.

  Версия связана с сообщением через `md5`, который записан в сообщении. Ревизия Drive хранит `md5Checksum`.
- Входящие и исходящие файлы — один список, у каждой версии стрелка направления: ↑ пользователь, ↓ агент.
- Сообщение хранит только ссылку: `driveRelativePath` (scratch), `sha256`, `md5`, `sizeBytes`. Содержимое в базу не попадает.

## 2. Срок жизни

- Drive сам удаляет незакреплённые ревизии старше 30 дней или сверх 100. Последняя версия остаётся всегда. Скрипта для этого не нужно.
- **Служебные (временные) файлы** живут 7 дней с последнего изменения (с 28.10, CO Web 0.56.1 и files-gc; было 30), затем удаляются целиком (в корзину Drive). Временными по умолчанию считаются:
  - код: `.py .ps1 .psm1 .sh .bat .cmd .js .mjs .cjs .ts .tsx .jsx .cs .java .go .rs .rb .php .pl .lua .sql .r .vbs .ipynb`;
  - всё в папках `tmp/`, `temp/`, `_tmp/`, `scratch-tmp/`;
  - логи `*.log`.

  В меню файла это переключается: «Keep» / «Temporary». Код, который нужен надолго, уходит в git (devtree или библиотека инструментов).
  CO Web 0.56.1: строка рабочих файлов под сообщением называется «Service files (N)»; так же свёрнуты служебные файлы во вкладке Files (правило isWorkingFile; если пользователь сам выбрал Keep или Service file — действует его выбор). 7 дней — только для kind temp (код, логи, tmp/); json, txt и прочие данные свёрнуты, но живут как документы.
- Файлы, поглощённые слиянием (`.versions/`), удаляются через 30 дней после слияния.
- Старые копии `artifacts/<job>/` удаляются, когда им исполняется 30 дней. Копии, совпадающие с живым файлом, удаляются сразу при переносе.
- Очистку делает cron на сервере (`cron/files-gc.php`, раз в сутки), отчёт приходит push-уведомлением.

## 3. Исполнители

- **Bridge 1.6.0.** Если рабочая папка лежит на Drive (scratch чата, папка проекта на G:), изменённые файлы не копируются. В результат идёт ссылка на сам файл с `md5`. Рабочая папка вне Drive — копия, как раньше.
  - Вложение с полем `target` Bridge кладёт прямо в `scratch/<target>`, перезаписывая файл. Это и есть новая версия от пользователя.
  - Вложение без `target` (старый CO Web) или в режиме с рабочей папкой вне scratch — по-прежнему в `.co-attachments/<job>/`.
- **Серверный агент.**
  - Перед заданием подтягивает из Drive `scratch` чата файлы, у которых `md5` отличается от локальных. Предел — 300 файлов и 200 МБ.
  - После задания пишет изменённые файлы в тот же `scratch/<path>` на Drive (`files.update`, новая ревизия), без копий в `artifacts/`.
  - Вложения с `target` кладёт в `scratch/<target>` и сразу выгружает на Drive.

## 4. Сервер

- Схема 12, таблица `chat_files`: реестр и пометки потоков.
  - Поля: путь, тип doc/temp и кто его задал, состояние live/merged/gone, `merged_into`, `extra_json` (`members` — файлы Drive, поглощённые слиянием; `parent` — откуда отпочкован; `restored`).
  - Голова: md5, sha256, размер, время, автор, номер сообщения.
  - Аннотация и md5, по которому она написана.
- `cron/files-sync.php` раз в минуту (из `drive-sync.php`) читает новые сообщения по курсору `meta.files_events_id` и заносит артефакты и вложения в `chat_files`.
- `cron/files-annotate.php` каждые 5 минут (из `watch-cron.php`), до 6 файлов за раз. Пишет аннотацию в одну строку (≤ 140 символов, о чём документ) через Claude Haiku. Источник — текст из `docs` (aiwb-docs), иначе имя и тип.
- `db.php`:
  - `files_list` — чтение, роль чата `read`;
  - `files_set` — тип или скрыть, роль `write`;
  - `files_merge`, `files_branch`, `files_restored` — роль `write`. Действия с Drive выполняет CO Web токеном пользователя, сервер их записывает.
- `job_events`:
  - при записи отбрасываются `tool_use_result`, подписи thinking, `rate_limit_event`, `thinking_tokens`, `tool_progress`, служебные поля сообщений;
  - `system/init` урезается до модели и сессии, результаты инструментов — до 4 КБ, ввод инструментов — до 16 КБ;
  - срок хранения — 14 дней;
  - накопленное сжимается одноразовым `db/compact-job-events.php`.

## 5. CO Web 0.55.0

- Вкладка **Files** вместо Artifacts. Видна только основная (последняя) версия каждого потока.
  - Наведение показывает тип («file» или «stream · N versions · you/agent») и аннотацию.
  - Меню ⋯:
    - Versions — список ревизий: дата, автор, сообщение; Download, Make main, Branch to new file, Delete;
    - Keep / Temporary;
    - Remove from list.
  - Перетаскивание файла на файл объединяет потоки. Отменить можно в течение 10 с.
    - Перенесённый поток становится частью целевого. Если его голова новее, она закачивается в целевой файл новой ревизией.
    - Файл перенесённого потока уходит в `scratch/.versions/`.
  - Make main закачивает содержимое старой ревизии новой ревизией (история остаётся линейной) и отмечает это в `extra_json.restored`.
  - Branch создаёт новый файл `<имя> (branch).<ext>` из ревизии, это новый поток с `parent`.
- Чип артефакта в сообщении открывает версию этого сообщения: голова, если совпал md5, иначе ревизия с этим md5. Если такой нет, пишет «version expired, showing the current one».
- Вложение в поле ввода:
  - если его sha256 совпадает с головой потока, это тот же файл;
  - если имя совпадает с потоком после нормализации (регистр, «(1)», `_v2`, `final`, `copy`, `edited`, хвост `_<инициалы>`), это новая версия этого потока;
  - иначе новый файл.

  На чипе написано «→ new version of report.docx», переключатель «separate file». В запрос идёт `target`, в сообщение — `target`, `md5` и `streamPath`. Отдельная копия в `branches/<b>/attachments/` больше не делается: пакет задания и есть доставка.
- Записка окружения агента: файлы чата лежат в рабочей папке; загрузки пользователя приходят новыми версиями тех же файлов; старые версии — в истории Drive; одноразовые скрипты класть в `tmp/`.
- CO Web 0.56.0: под сообщением рабочие файлы агента (`isWorkingFile` в `chatFiles.ts`: временные — код, логи, `tmp/`; данные и состояние — json, jsonl, txt, tsv, yaml, xml, ini и т.п.; файлы без расширения, в скрытых папках и короче 16 байт) свёрнуты в одну строку «N working files · имена…», раскрываются по клику. Во всех чатах, у всех пользователей. Только отображение: kind и срок жизни файлов не меняются.

## 6. aiwb-docs

Индексирует `scratch` (живые копии) и пропускает `artifacts/` и `.versions/`. Повторы из `docs` уходят.

## 7. Перенос того, что есть (после выпуска)

1. Снимок базы до изменений: `backups/db/pre-files/pre-files-20261028.sql.gz` (171 МБ).
2. Сжатие `job_events`.
3. `chat_files` заполняется по всем сообщениям.
4. Копии `artifacts/<job>/`, побайтно совпадающие с живым файлом, уходят в корзину Drive, ссылки в сообщениях и результатах заданий переписываются на `scratch`.
5. Остальные копии остаются старыми версиями, пока им не исполнится 30 дней.
6. Индекс `docs` пересобирается.

## 8. Отмена изменений задания (CO Web 0.72.0, 2026-11-01)

- Под ответом агента с файлами — «↶ Undo changes of this job». Превью: каждый файл с галочкой и действием.
  - **restore** — файл был до задания: его ревизия Drive, предшествующая ответу, закачивается новой ревизией (как Make main; версия ответа остаётся в Versions). Ревизия «до» — новейшая перед ревизией ответа (md5 ответа, записанная после начала задания), которая старше сообщения пользователя или совпадает по md5 с версией из более раннего сообщения чата или с загрузкой пользователя в это задание.
  - **trash** — файл создан заданием (нет более ранних версий в сообщениях, создан после начала задания): в корзину Drive (30 дней). По умолчанию не отмечен: Drive не различает, кто создал файл (агент и пользователь пишут одним аккаунтом).
  - **—** — откатить нельзя: файл не менялся, версия «до» истекла (Drive хранит ревизии 30 дней), файл удалён, Google-документ без md5.
  - Файл, изменённый после ответа (следующим заданием или вручную), показан с предупреждением и по умолчанию не отмечен.
  - Вне `chats/<чат>/scratch/` на Drive, старые копии `artifacts/<job>/` и «not exported» — строками «cannot undo»; команды, почта, git и прочие действия задания не откатываются.
- Ревизия задания — только датированная Drive не раньше сообщения пользователя (без допуска на часы: при сбитых часах файл просто не откатывается). Перед записью файл ищется заново по пути: другой id (перенесён/заменён) или другой md5 после превью — пропуск. Сбой записи в базу показывается в итоге. Папки не трогаются никогда (папка чата в корзине = удалённый чат).
- Сервер: `db.php` `files_undone` (роль `write`, `files-lib.php`): по пути потока; restore — `extra.restored` (с `undoOf`) и новая голова, trash — `state = gone`; оба пишут `extra.undone`. Поток без строки в `chat_files` пропускается.
- Логика плана — `co-web/src/undoPlan.ts` (самопроверка `undoPlan.selftest.ts` в `npm test`), Drive — `undoJob.ts`, окно — `UndoPanel.tsx`.
